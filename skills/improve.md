# improve

Give signals in scope a grounded disposition and complete the change the human approved.
Keep the decision, evidence and remaining work on the record they concern.

## Assess friction when needed

Start from the caller's scope and existing work.
Read relevant findings and corrections, including reviewed corrections that establish recurrence.
Reuse current evidence until relevant state changes or freshness is uncertain.
Use qualified family queries when discovery is needed.
Page completely before claiming coverage or absence.

Group findings by breaks.
Follow recurs to the original correction.
Set a missing recurs link when a return is recognized.
A backlink count alone does not establish recurrence.

Mark an assessed correction reviewed when no action is pending.
Preserve the feedback and record the reason there.
A first occurrence can remain watched without a proposal.

Use [[propose]] for a supported change that needs a proposal.
Supply its requirement, evidence and constraints.
Use [[derive]] for a new capability gap whose methods need investigation.
Use [[self-research]] for a known methodological gap.
An adequate existing route needs no new proposal.

## Build within approval

Use the human's recorded ruling and approval already given in the session.
Silence grants no approval.
Resolve ordinary implementation choices within that scope.
Return a material scope change through propose for a ruling.

Use each mechanism's owning authoring capability.
For example, [[write-a-skill::au-skills]] authors skills and [[write-a-rule::au-writing-style]] authors writing rules.
For contract changes, use [[design-for-growth::au-agent-guides]].
Account for affected consumers and preserve a resumption point during migration.

Observe the result through its intended consumer.
Follow the owner's discovery, selection and activation contract.
A profile link does not establish invocation.
A field grants no operation additional effects.

Match checks to the promised behavior.
A prevention claim needs an exercised boundary.
A semantic claim needs judgment against its doctrine.
Record source and runtime revisions when they determine the result.
Reuse unaffected evidence and keep checks within authorization and privacy constraints.

## Record demonstrated completion

Keep the proposal accepted while promised behavior remains unproven.
Name the remaining obligation and next action.
Continue independent approved work where possible.
Never weaken a requirement to make completion appear true.

For fulfilled competencies in answers, record competency-question.answered with answered_by pointing to the working capability.
A verification artifact can identify a distributed result and its observed evidence.
A design alone does not establish fulfillment.
Preserve an adequate existing answer.

A completed prerequisite leaves the larger competency open.
For example, a delivered component cannot close a requirement that also promises an untested integration.
Record the delivered scope and keep that integration obligation visible.

Forge only corrections whose friction the demonstrated remedy addresses.
Set forged_into to the remedy.
Follow recurs dependencies root first.
Do not forge an unresolved root merely to permit a return's transition.

The dependent states require this order:
1. Record fulfilled competencies and demonstrated remedies on recurrence roots
2. Record dependent forged corrections and mark completed proposals implemented
3. Read the saved transitions and inspect diagnostics

Write through the engine.
Repair introduced errors and assess relevant warnings before relying on any changed record.
A successful write can still leave a state mismatch.
Keep the outcome and any recovery work on the proposal or existing work artifact.
