# derive

Return grounded [[competency-question.open]] records for capabilities the workspace needs.
State the requirement without choosing its implementation.
Keep unsupported candidates on the caller's existing work.

## Decide whether a question is needed

A candidate must serve the relevant workspace premise and have both:
- Recurring friction or research corroborated by a real signal
- Missing methodological knowledge that could change the design

Read the premise's purpose and boundaries.
If none is established, return that dependency.
This skill does not establish the initial premise or create speculative onboarding questions.

Use [[a-kind-or-a-question::au-agent-guides]] when a modeling choice may need only existing guidance.
A new type alone does not justify research.
Send a supported remedy to [[improve]].
A violation of existing doctrine belongs to au-govern.
Subject questions belong to au-tree-research.

## Ground the requirement

Use supplied evidence and current engine results.
Read further only where grounding or scope remains uncertain.

Group findings by their breaks relation.
Follow corrections' recurs relations to the original occurrence.
Several findings can establish recurrence, as can a reviewed correction handed back again.
A common label or backlink count alone cannot.

Check relevant competencies across their states.
Reuse an equivalent open question and respect a dropped disposition.
Inspect an answered question's working answer before declaring the capability missing.
A regression needs a new question, leaving the terminal record intact.

Discover records with qualified family queries when needed.
Page completely before claiming coverage or absence.
Refresh reads when relevant state changes or freshness is uncertain.

## Save the useful result

Use the current competency-question.open contract:
- The title states the requirement
- from identifies the grounding signals
- serves identifies the workspace premise

Explain the stakes and what success would look like in the body.
Keep candidate mechanisms distinct from conclusions.
When several gaps qualify, prioritize by their consequences and evidence.

Write through the engine.
Read the saved result for meaning and inspect write diagnostics.
Repair introduced errors and assess relevant warnings before relying on it.

Return question references and any held gaps with their reasons.
Keep dependencies and next actions on the caller's existing work.
[[self-research]] investigates methods, [[propose]] develops changes and [[improve]] implements approved scope.
